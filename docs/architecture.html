Data flow & AI surface map

Grocery Basket Optimizer

A lightweight medallion pipeline over DC-metro grocery prices, with LLMs embedded at exactly three judgment points — always behind deterministic gates, never on the write path to gold.

The load-bearing design principle

The LLM proposes; the pipeline disposes. Agents adjudicate ambiguity and narrate results — they never invent data, never fabricate a join, never write to gold. Every number a user sees is queryable from a gold view and traceable through silver to a raw bronze artifact. This is the argument for LLMs in production data pipelines: judgment where fuzzy logic fails, determinism everywhere else.

Where the AI actually sits — four surfaces, each behind a gate

Built · shipping

Entity-resolution adjudicator

RapidFuzz auto-links the easy ~80% of cross-store product matches. The ambiguous band queues to Claude, which returns a structured same-product verdict with confidence. The pipeline — not the model — applies links at ≥0.85; everything weaker goes to human review. Gate: LLM output is a verdict row, never a database write.

Built · shipping

Category guard + verdict cache

A deterministic coarse taxonomy (form beats ingredient: "chicken crackers" is a snack) hard-blocks cross-category matches before any fuzzy score or token is spent. The verdict cache makes each adjudicated pair cost one LLM call ever — cached verdicts compound into a proprietary regional matching library, and gold reads only the cache, so replay is fully deterministic.

Planned

Parser self-healing agent

When a retailer changes their response schema, the agent diffs new raw structure against expected, proposes a patched parser, and re-parses last known-good bronze files. The patch promotes only if output matches — a deterministic validation gate on generated code.

Built · shipping

Weekly plan narrator

Writes one paragraph from a deterministic gold fact pack (every total and delta precomputed). A hard audit gate extracts every number from the prose and rejects the narration if any number is missing from the fact pack — nothing unaudited is stored or served. Citations (gold price row IDs) are appended by the pipeline, never emitted by the model; the PWA serves stored narrations at zero tokens per view.

Medallion architecture Yes Genuine bronze/silver/gold with the vocabulary used correctly — and a good FDE story about right-sizing: medallion semantics on DuckDB + files instead of reflexively reaching for Spark/Delta. Immutable raw layer, idempotent re-parse, lineage via manifest IDs.
LLM inside a data pipeline Yes The strongest claim here. LLM-as-adjudicator on the entity-resolution long tail, with confidence thresholds, human-review fallback, structured outputs, and deterministic replay via the verdict cache. This is production LLM engineering, not a chatbot demo.
Agentic systems Yes Three agents live behind deterministic gates: the entity adjudicator (confidence thresholds + human fallback), the list-term adjudicator with its verdict cache, and the narrator with a number-audit gate that rejects any prose gold can't vouch for. One designed agent remains (self-healing parser). "Agents behind gates" is the senior version of this story.
RAG No No embeddings or vector store — by explicit design decision. RAG is covered by other projects in the portfolio; this one is the counterweight: exact-key verdict retrieval beats semantic retrieval when matching must be auditable and replayable. Together they show you pick the retrieval strategy per problem, not by default.
GraphRAG No Not here — demonstrated by other portfolio projects. The canonical-product graph (products ↔ stores ↔ verdicts) is knowledge-graph-adjacent and a natural bridge when presenting the portfolio as a whole, but don't label this project GraphRAG itself.
